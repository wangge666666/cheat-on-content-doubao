# 豆包工作宿主适配协议

## 保留范围

原版 15 个子技能、总协议、共享协议、starter rubrics、模板、迁移、全部平台数据适配器、Whisper 转录和辅助工具按字节复制到 `assets/cheat-on-content/`。`source-manifest.json` 记录每个原版文件的 SHA-256；`doctor` 检查这些资源是否被改动。接入包的根技能通过路由加载完整原流程。

安装包使用单一入口承载全部技能；它不是只装了一个功能。内部 `cheat-score-blind` 保持内部身份，不注册为供主对话直接执行的用户技能。

## 文件系统

- 技能目录只放规则与代码；账号数据使用单独且实际可访问的目录。不得将账号凭证放进技能资源或重打包上传。
- 豆包云端命令看不到 Mac 的 `/Users/...` 路径。需要在当前环境上传所需素材或通过平台提供的授权机制访问；不能把本机脚本执行结果当成云端验证结果。
- 持久目录与跨会话可见性必须实际验证。需要重新选文件夹时保留旧数据，不新建空目录冒充原账号。

## 初始化及状态

完整执行原版 `cheat-init` 的问题、模板复制和配置流程，schema 以 `migrations/registry.md` 为准。原版 hooks 问题在豆包中解释为“启用本接入的预测写入保护和调用时状态报告”；不要注册无效的 Claude hooks，也不要伪标 `hooks_installed=true`。

初始化完成后运行 `protect` 建立当前预测的保护基线。`session` 每次技能调用时运行，复用原版 `hooks/session-start.sh` 渲染库存和待办。它不等于豆包平台的全局会话启动钩子；未调用本技能的新聊天不会自动执行这段脚本。

## 预测保护

`write` 对拟写入的完整文件进行检查：任何已经保存的 `## 预测` / `## 预测 v1` / `## 预测 v2` / `## Prediction` 段均不得修改、删除或重排；允许改文件头、追加复盘、追加新版本或新建 `_redo` 文件。代码围栏内的示例标题不充当实际段落边界。

保护基线在内容项目 `.cheat-guard/predictions.json`，应与预测文件一起备份或纳入私有版本管理。`verify` 检测已封存文件被其他工具修改、删除或改成符号链接的情况。完整性失败时停止写入并从备份核对；不要删账本“修复”。首次建立基线只证明此后的完整性，不证明此前从未改动。

**工程边界**：这是专用写入通道的前置阻止与后续检测，不能拦截豆包所有文件工具、外部编辑器或终端命令。不要声称已经移植了全局 PreToolUse 拦截。所有按本技能执行的预测文件修改必须经过 `write`。

## Channel B：隔离盲评分

`blind-score` 只读取账号中明确指定的 `scripts/*.md` 与 `rubric_notes.md` 作为模型材料；模型连接配置只在本地用于鉴权，不加入请求正文。每次 API 调用独立构造两条消息，不发送主对话、state、benchmark、audience、rubric-memo 或任何复盘报告，也不给远端模型文件系统工具。

评分说明取自完整原版 `cheat-score-blind/SKILL.md`，将其中文件读取动作映射为已内联的两个文件正文。返回值必须符合原 JSON 结构，包括稿件路径/哈希、当前公式完整维度、分数、理由、置信度、输入自检和污染自检。保留原版 `non_blind_warning` 分支：仍返回维度，全部 confidence 为 medium，保留污染标记并由主流程按原协议处理；不能把这种结果标记为“无污染盲评通过”。其他拒绝或校验失败不视为有效评分。

这解决输入隔离，不保证模型的分数等同于原 Claude，也不消除评分规则本身的偏差。原主流程的 disagreement review、用户 override 留档、confidence 和复盘纪律保持。

原文的“主 Claude”在此指当前豆包编排者。模板字段名称保持，`Scored By` 等字段值按真实模型记录，`BlindScored By` 标注独立 API 通道及真实模型，不冒用 Claude 或原生子代理身份。

`cheat-bump` 的新规则需要先准备**临时评分目录**：只放全部待评原稿和新的通用 `rubric_notes.md`，以及模型配置。逐稿调用该临时目录的 `blind-score`。在完成重评、本地检验和外部审核前，不提前覆盖账号的生效规则。临时目录不得包含实绩、预测或 memo。

## Channel C：跨模型审核

在原本地验证通过后，由主流程生成 JSON：

```json
{
  "old_formula": "旧公式的完整方程",
  "new_formula": "新公式的完整方程",
  "samples": [
    {"id": "匿名样本ID", "dimensions": {}, "old_composite": 0, "new_composite": 0, "actual_plays": 0}
  ],
  "ranking": {"threshold": 0.8, "rank_table": [], "pairwise_no_regression": true}
}
```

上面仅表示结构，不能把示例零值提交为真实校准池。实际材料包括原协议要求的全部维度、真实统计和排序结果。`audit` 使用单独配置的其他模型，返回 `verdict=PASS|REJECT`、至少 100 字的理由和风险列表。不同模型是实质要求，不仅是两个不同 API Key；建议评分用豆包，审核用通义千问。脚本可排除明显相同的模型 ID，不能自动识别所有供应商别名。

REJECT 会以非零退出码返回；缺配置、HTTP 错误、异常 JSON、理由不足均视为未通过。仅重校 bucket 使用原版轻量流程，不无故增加跨模型审核。

## 适配器及其他功能

`collect` 将账号目录、原版脚本和实际作品 ID 传给原 `run.sh`，账号登录态与报告仍写在该账号内。依赖未安装时按原适配器的 requirements 配置，扫码等交互由用户在对应浏览器完成；不能从其他账号复制登录态。源代码已打包不代表当前平台接口已成功登录或抓取。

Whisper、误差曲线、稿件差异、热点数据源和 humanizer 依照随包原文调用；源码根目录统一解析到 `assets/cheat-on-content`。未提供的外部服务仍需配置，不把人工输入冒充自动抓取。

## 验收标准

分开报告：原版文件校验、桥接脚本测试、豆包成功导入、豆包内脚本运行、两条模型通道实调、各平台采集实调。未执行的项目写“未验证/待配置”。全部 15 个技能保留不等于这些运行依赖全部已就绪。
